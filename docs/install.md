# Installation and update contract

The [user guide](https://docs.fased.ai/guide/install) describes the customer flow. The shared Fased plan defines the packaged Linux architecture, Current records its status, and the shared implementation plan owns B01's checklist.

Recorded 0.1.11 installation/update and distribution evidence remains valid for its original environments. Attested dual-arch Linux Local and mandatory-Tailscale Remote installation/updates (`v0.2.0`, `linux/amd64` + `linux/arm64`) and dual-track cross-platform CLI & unsigned desktop pre-releases (`v0.2.0-desktop`) are published; the required path is a terminal installer for one verified prebuilt core/signer bundle, a browser-based wizard, fixed app/signer services and persistent data, and one UI/CLI Update/recovery operation. Format-4 installation, `internal/vpsnetwork` dual-stack firewall/SSH lockdown, `fased-app host migrate-units`, `install.sh --remote --refresh-helper` (supporting chained helper transitions and required once on pre-`0.1.45` Format-4 Remote hosts on `v0.1.45` before updating to 9-asset `v0.2.0+` releases), and dual-arch attested release assembly cover Ubuntu 24.04/26.04/26.10, Debian 12/13, and Fedora 41–45 on `linux/amd64` and `linux/arm64`. `apt`/`dnf` is used only for needed OS prerequisites; a desktop client is not required.

- **Local setup.** Reuse the human OS owner. Initial OS approval installs the protected package and isolated service identities. Open the authorized loopback browser with an empty signer. Wallet setup initializes its reserved vault through the same installation identity.
- **Remote setup.** On the VPS, establish Tailscale enrollment and private reachability before Fased deployment. Bind the owner/device, prepare protected HTTPS and verify private administration plus independent console/rescue access. Restrict owned public access through the existing rollback-capable transaction, preserving foreign routes and essential networking. Close bootstrap SSH after private access and recovery pass.
- **Routine Update.** Settings and installed `fased update` use the same authenticated release, controller, operation ID, progress/result and journal. Reuse Local OS-owner or Remote owner/device authority. The original setup grants routine maintenance access. Missing or revoked access produces a specific recovery action.
- **Interrupted Update.** Recover the original authenticated target through the installed entry and boot recovery. Check package/core/signer/schema compatibility and retain keys, data, authentication and financial holds. Serialize concurrent requests and reconcile an uncertain result before further execution.
- **Acceptance.** Prove actual fresh setup and version-changing UI/CLI Update, interruption/reboot, preserved state and Already current on real Fedora first. Then verify Ubuntu Local and affected Tailscale Remote on the named real VPS. Use the approved labeled non-public Fedora predecessor. Disposable keys remain controlled acceptance inputs. Current selects exact targets and inherited evidence.
- **Delivery.** Dual-track installers share the same Go core, isolated signer, and web client: (1) CLI/server archives installed via `curl`/`install-cli.sh` (Linux/macOS) or `irm`/`install.ps1` (Windows) with opt-in `--upgrade`/`-Upgrade` in-place upgrades, and (2) native desktop packages (`.dmg`, Windows `.exe`, Linux `.deb`/`.AppImage`) staged by `scripts/package-native.mjs` and assembled with `scripts/assemble-dual-track-release.mjs`. Required browser and joined UI/CLI checks run independently of optional desktop packaging. Candidate and eventual public builds keep real-host evidence and publication admission authoritative.
- **Retirement.** Remove replaced code after its callers, service definitions, supported predecessors and pending journals are accounted for. Preserve required compatibility readers and original recovery state with explicit remaining consumers. Legacy `internal/vpsinstall` and `internal/enrollment` app-only paths are retired at `v0.2.0` in favor of `internal/vpsnetwork` and Format-4 `internal/custodyinstall`.

Manual installation/update acceptance closes at that actual installed result. The [release guide](maintainers/ubuntu-release.md) separately requires authenticated package evidence, installed agent acceptance and publication authority. Customer Automatic, mining and live execution remain held. Select additional shared-controller checks only for changed behavior or a specific unresolved concern.

Before real-wallet use, complete protected setup and independent encrypted backup/restore in B05. [Recovery and availability](https://docs.fased.ai/guide/install#recovery-and-availability) records the access-provider boundary. Existing keys, credentials, data and recovery holds remain protected throughout maintenance and code retirement.
