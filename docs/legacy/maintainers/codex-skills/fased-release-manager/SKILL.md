# Fased workflow

Use the selected checkout and scoped AGENTS.md. Universal instructions govern
authority, evidence and preservation. Preserve independent review required by the plan.

- Questions/reports: inspect source; no delivery workflow.
- Implementation: select the component authority from its scoped AGENTS.md: Fased App uses `/home/fc/fasedbot/docs/fased/execution.md`; WEN uses `/home/fc/fasedbot/docs/wen/execution.md`. Start at that current checkpoint. Complete the connected journey and affected checks, not isolated helper milestones. Continue authorized local work without repeated approvals.
- Delivery: classify the final diff once, use the protected PR, merge only the authorized exact passing head, then read back canonical identity. Never bypass branch protection.
- Ordinary fixes use focused checks and produce no release artifact.
- When parallel work is authorized, record the selected agent count, shared interface, disjoint file ownership and one coordinator in the current checkpoint. Keep custody/accounting/recovery integration under that coordinator; no task or evidence receipt per helper.

## Authorized parallel work

Record authorized deliverables in Current; use a spare worker for independent review, not duplicate exploration.
Workers return files/hashes, checks, findings and blockers, then stop edits. Freeze inputs before the joined matrix; after corrections rerun only affected checks and reuse compatible evidence.
Isolate mutable state, ports and outputs; serialize shared resources and preserve caches. Agent count is checkpoint-specific; coordination changes no authority, economics or model selection.

Use the existing owner installation for authorized runtime proof; fresh Local or
Hosting environments remain owner-authorized. Never handle sudo passwords or run
project code as root. Managed releases are GitHub-only; npm is not managed update
authority. Reuse saved GitHub authentication; do not restart pending device flows.

Freeze edited inputs before verification; refresh artifacts once and reuse unchanged evidence. Update the
tracker's current checkpoint once per meaningful milestone. Keep WEN Current
compact with a retained-history link and finite core, optional Fased and later
acceptance gates. Apply mandatory disk hygiene from tests.md before final
reporting; retain keys, state and unique work.

Separate implementation, controlled verification, live acceptance and release.
Live holds allow authorized production-path implementation against controlled endpoints, with production dispatch/credentials disabled and test injection isolated.
Finish reviewable code before requesting live acceptance; continue independent ready core work when external gates block acceptance.
Fixture PASS is not product completion. Do not manufacture helper/inventory milestones. Docs-only corrections authorize no code or activation.

Define a connected package; inspect affected API/storage/UI consumers before verification. Fased App uses `docs/fased/implementation.md`; history is not a queue.
CI uses protected-base policy and the whole PR diff. Record broad-PR constraints; never bypass gates or claim unmeasured speedups.

Queue the next task only with an executable completion path: exact deliverable,
owned files and completion command/check. Label unavailable dependencies and
continue independent ready work.

Repeated partial or selected evidence cannot close a complete milestone. Resolve
the missing source or owner decision once instead of adding more helper proofs.

Mandatory closeout gate: before a final handoff or next milestone, automatically
review the outcome, rework/retries, agent dependencies, reused checks/caches,
cleanup and the next critical-path task. Do not wait for an owner reminder.
Correct demonstrated in-scope causes now, verify only affected checks, and update
the existing plan or canonical skill when that prevents recurrence; synchronize
changed skills. Keep the review bounded: no speculative optimization, extra
benchmark, new tracker or guidance rewrite when no change is justified.
For implementation and workflow edits, record one `**Execution review:**` line in
the Current checkpoint: `PASS` or `BLOCKED`, with `outcome=`, `correction=` (or
`none justified`), `verification=`, `reuse=`, `cleanup=` and `next=`. PASS confirms
the review and recorded disposition, not overall product readiness. An unresolved
in-scope correction remains BLOCKED; external dependencies stay explicit. Never
mark the affected milestone complete before its required correction/check passes.
Stop owned runners and remove only verified task-owned disposable outputs after
retaining evidence; preserve keys, state, unique work and compatible caches.
Record any retained path and deletion condition. Reports remain read-only; their
review does not authorize edits. Never change economics, authority or financial/
recovery safeguards, invent efficiency gains, or resume paused implementation.
