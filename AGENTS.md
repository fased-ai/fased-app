# Fased App contributor notes

- This is the new application; the sibling `fased` and `server` repositories are reference sources, not dependencies.
- Product/phase authority: `../docs/fased/plan.md`, `implementation.md`, and the Current checkpoint in `execution.md`.
- P2 adds the private Go core, owner authentication, app-owned SQLite, and shared UI/CLI setup. Terminal, agent and wallet content is still explicit prototype data; no wallet keys, provider credentials, RPC or financial execution. WEN terminals remain labelled prototypes.
- Keep shared UI/state independent of a desktop shell. Add Go runtime modules in their planned phase rather than scaffolding them upfront.
- The `desktop/` Go module pins Wails separately so core/VPS builds do not acquire desktop dependencies. It is an IPC-backed client with no generic Go bindings; window close never stops the engine. Its smoke runner is development-only.
- `install`, `service`, `open` and `uninstall` implement ordinary-user engineering installation: systemd on Linux, launchd agent on macOS, limited interactive-user task on Windows. No root execution, release acquisition or in-place binary replacement. Autostart is opt-in; uninstall verifies its inventory, resumes interrupted removal and preserves all instance data and unknown files. `docs/install.md` owns current package/private-access/recovery instructions. Packages remain unsigned engineering outputs; their hashes are not publisher authenticity.
- Original code uses PolyForm Perimeter 1.0.0. Preserve third-party terms/notices; record any copied source and its revision. Do not import the legacy code tree.
- Development: `npm ci`, `npm run dev` for the fixture UI. `npm run build` then `npm run build:core` embeds the production UI. The core requires Go 1.26; no Node runtime is required by the compiled application.
- Verify affected behavior with `npm run check`, `npm run test:core`, `npm run test:ui`, and `npm run test:core-ui`; use `git diff --check`. Core browser tests need the built binary. Test state is disposable, reconstructible and nonauthoritative; results belong in `.evidence/`.
- Native source: `npm run build:desktop` needs GTK3/WebKitGTK 4.1 development packages on Linux, Xcode on macOS, and the Windows WebView2 runtime for execution. `npm run test:native-window` needs the Linux smoke binary and Xvfb. `scripts/check-local-install.mjs` requires explicit current owner authority and `FASED_LOCAL_ACCEPTANCE=1`; it changes the real user's previously absent service with only declared generated fixtures.
- Ubuntu `--prepare-host` and the terminal wizard may authorize fixed trusted OS package/profile tools. The application never runs as root. Verify policy bytes against the compiled digest, publish exclusively, preserve foreign/loaded policy and durable retry intent; never use a root shell, overwrite profiles or relax global AppArmor settings. Privileged acceptance is disposable Ubuntu CI only; owner Fedora tests remain unprivileged.
- Guided Tailscale configuration is Linux-only and uses the local daemon ETag/If-Match contract; never reset owner routes or change enrollment/SSH/firewall/login policy. Keep the listener loopback-only, CLI transport OS-protected, owner/session material private, and setup writes revision-checked. Never make a demo preference imply a connected account or signing authority. Core state and future signer state have independent owners.
- Browser evidence and disposable test outputs belong in ignored `.evidence/`. Preserve failure evidence until resolved; delete only task-created reconstructible artifacts.
